# 🚨 v1.9.3 - CPU OVERLOAD FIX

## THE PROBLEM (v1.9.1 & v1.9.2):

At 600 RPM stepper (8000 sps, 1200 RPM spindle):
```
Motor: Running smooth ✓
Tach: 600 RPM confirmed ✓
Encoder: DEAD ❌❌❌
```

---

## ROOT CAUSE: CPU OVERLOAD

**At 8000 sps, the CPU can't keep up!**

### CPU Load Breakdown:

```
ISR (every 50μs = 20 kHz):
├─ Drain encoder FIFO: 32 samples × 4 bytes = 128 bytes
├─ Decode quadrature: 32 × table lookup
├─ Write step PIO FIFO: 8 bytes
├─ Move queue logic
└─ Total: ~15 μs CPU time!

Main Loop:
├─ Update RPM: float math
├─ Sync traverse: math + queuing
├─ LCD I2C: blocks for ms!
├─ Printf to USB: blocks for ms!
└─ Winding logic

Result: CPU at 100%! Encoder ISR can't run! ❌
```

### Old Encoder Sample Rate:
```
PIO clock: 125 MHz / 100 = 1.25 MHz
With [7] delay: 1.25M / 8 = 156 kHz samples/sec

At 1200 RPM spindle:
- Expected events: 28,800/sec
- PIO samples: 156,000/sec (5.4x oversample)
- ISR drain: 32 samples/tick × 20 kHz = 640,000 samples/sec processed!

Too much work! ❌
```

---

## THE FIX (v1.9.3):

### **10x Slower PIO Sampling**

```c
OLD: sm_config_set_clkdiv(&c, 100.0f);  // 156 kHz
NEW: sm_config_set_clkdiv(&c, 500.0f);  // 25 kHz ← 6.25x slower!
```

**New sample rate: 25 kHz**

### **Reduced ISR Drain**

```c
OLD: while (...samples_processed++ < 32)  // Process 32/tick
NEW: while (...samples_processed++ < 16)  // Process 16/tick ← Half!
```

---

## 📊 NEW PERFORMANCE:

At 1200 RPM spindle (8000 sps):
```
Encoder events: 28,800/sec
PIO samples: 25,000/sec (0.87x oversample) ⚠️ Barely enough!
ISR drain: 16 samples × 20 kHz = 320,000/sec processed
ISR time: ~7 μs (half of before!) ✓

CPU load: ~50% (much better!) ✓
```

**Will this work?**
- ✅ At 600 RPM: 14,400 events/sec vs 25k samples = 1.7x ✓
- ⚠️ At 1200 RPM: 28,800 events/sec vs 25k samples = 0.87x ⚠️

**Marginal at full speed, but should work at 600 RPM!**
