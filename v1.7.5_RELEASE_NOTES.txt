THE BUG YOU FOUND:
============================================

You described it perfectly:
"ramp starts real slow smooth then goes boom boom tops out 
soon as the ramp finish it drop way slower to wind"

Serial proved it:
```
Ramp up: All 24 slices queued to PIO
[CONTINUOUS] Queuing 4500 steps @ 3000.0 sps (150 RPM)  ← SPIKE!
[ENC] pos=7236 rpm=223.8  ← 225 RPM! (boom boom!)
[CONTINUOUS] Re-queueing 1200 steps @ 800.0 sps (60.0 RPM)  ← Drop!
[ENC] pos=11098 rpm=96.9  ← Slowing down
[ENC] pos=11825 rpm=60.5  ← Finally settles
```

============================================
ROOT CAUSE:
============================================

There are TWO places that queue continuous movement:

1. **End of ramp_up_spindle()** (line 367-375)
   - This queues the FIRST continuous movement
   - Was using: MOTOR_MICROSTEPS (16x) = WRONG!
   - Was using: 3000 sps max = TOO FAST!
   - Result: Brief spike to 225 RPM! ❌

2. **execute_winding() refill** (line 395)
   - This re-queues when FIFO gets low
   - Was using: SPINDLE_MICROSTEPS (4x) = CORRECT! ✅
   - Was using: 800 sps for 60 RPM = CORRECT! ✅

Result: Motor "boomed" to 225 RPM, then dropped to 60 RPM!

============================================
THE FIX IN v1.7.5:
============================================

Changed line 367:
```cpp
BEFORE:
float steps_per_rev_f = 200.0f * MOTOR_MICROSTEPS;  // 16x = 3200 steps
const float max_sps = 3000.0f;

AFTER:
float steps_per_rev_f = 200.0f * SPINDLE_MICROSTEPS;  // 4x = 800 steps
const float max_sps = 6000.0f;
```

Now both transitions use the same math!
